# 展示层对齐 — 设计规格

> 日期：2026-06-28
> 基线：`PRODUCT_DESIGN.md` v1.3
> 范围：Dashboard 图表拆分 + CPL 降级 + 菜单栏精简 + 欢迎页补全

## 1. 背景

当前实现与 `PRODUCT_DESIGN.md` v1.3 存在 5 处偏差。本次变更分两批量收敛：

| 批次 | 范围 | 性质 |
|------|------|------|
| 展示层 | Dashboard 图表拆分、CPL 降级、菜单栏精简 | UI 重构 |
| 逻辑层 | 欢迎页 Step 3（仓库选择） | 新功能 |

## 2. 展示层变更

### 2.1 Dashboard — 拆分为两张独立图表

**现状**：`DashboardView.swift` 的 `combinedChart` 将花费（Cost Bar）和代码行数（Lines Bar）画在同一张图，使用双 Y 轴。

**问题**：同轴暗示花费与产出存在相关关系，而设计 1.2 节明确指出二者"无必然同调"。

**方案**：替换为两张上下堆叠的独立图表。

#### 图 1 — 花费图

- **类型**：堆叠柱形图
- **X 轴**：日期（7 天或 30 天，复用现有 `dayRange` Picker）
- **Y 轴**：USD
- **数据层**：
  - **下层**：C 级订阅均摊（月费 ÷ 当月天数）。每个启用的 C 级工具各一个颜色。每日恒定值。
  - **上层**：B 级 API 余额消耗。每个已配 Key 的 B 级 provider 各一个颜色。每日波动值。
- **堆叠逻辑**：多个 B 级 provider 在上层叠加，多个 C 级订阅在下层叠加。每个集成独立着色。
- **悬停 Tooltip**：日期 + 各 provider/工具拆分数字
- **注脚**：`⚠️ 两类花费独立展示，不参与 CPL 计算`
- **数据来源**：B 级 `usage_event` 按 provider 分组 + C 级订阅按月费/天数即时计算

#### 图 2 — 代码变化图

- **类型**：堆叠正柱图（新增 + 删除均用正柱）
- **X 轴**：日期
- **Y 轴**：行数
- **数据层**：
  - 新增（added）：一种颜色
  - 删除（deleted）：另一种颜色，堆叠在新增之上
  - 总柱高 = added + deleted，代表当日代码变更总量
- **悬停 Tooltip**：`+230 新增 / -45 删除`
- **数据来源**：`code_change` 表，按日聚合 added/deleted

### 2.2 Dashboard — 摘要卡调整

```
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐
│ 本月已花   │ │ 本月预估   │ │ 本周增减行 │ │ 订阅日均   │
│ $45.20    │ │ $98.00    │ │ +1200/-340│ │ $2.30     │
└──────────┘ └──────────┘ └──────────┘ └──────────┘
```

| 变更 | 原 → 新 |
|------|---------|
| avg CPL 卡 | 删除 |
| 总行数 卡 | 替换为"本周增减行"（`+added/-deleted`） |
| 新增 | "订阅日均"卡（所有 C 级工具月费之和 ÷ 当月天数） |

### 2.3 Dashboard — CPL 降级

**删除**：独立的 CPL 趋势图（橙色折线 `LineMark` + `PointMark`，`DashboardView.swift:287-339`）。

**新增**：底部辅助卡片行中的 CPL 数字小窗（仅在有效门内显示）：

```
┌─ CPL（每千行成本）─────────────────────────┐
│ 本周 · repo-a    $2.35/千行                │
│ 本周 · repo-b    $1.80/千行                │
│                                              │
│ ℹ️ 按量计费 · 有日志                        │
│   仅含 API Token 成本，不含订阅              │
└──────────────────────────────────────────────┘
```

- 按 repo 列出精确 CPL，不跨 repo 求总
- 不画折线图，纯数字展示
- 有效门：A 级集成已启用 ∧ 有日志数据（即 `hasAGrade`）
- 无有效 CPL 时展示引导卡片（复用现有 `cplGuidanceCard` 逻辑）

### 2.4 Dashboard — 底部辅助卡片行

```
┌─ API 余额 ────┐ ┌─ 订阅消耗 ────┐ ┌─ CPL 小窗 ────┐
│ (B 级数据)     │ │ (C 级数据)     │ │ (仅有效门内)   │
└────────────────┘ └───────────────┘ └───────────────┘
```

- API 余额卡：复用现有 `apiBalanceCard`
- 订阅消耗卡：复用现有 `subscriptionCard`
- CPL 小窗：新增，见 2.3
- 三张卡永不求和

### 2.5 菜单栏精简

| 位置 | 新格式 | 说明 |
|------|--------|------|
| 今日摘要 | `今天 · $2.35 · +230/-45 行` | CPL 移除，token 数移除 |
| 本周摘要 | `本周 · $12.80 · +1200/-340 行` | 同上 |
| Provider 子菜单 | `OpenAI · $2.35` ... | 改用 B 级余额数据（`ApiPoller`），按花费排列 |
| 仓库子菜单 | `my-repo · $2.35 · +230/-45 行` | CPL 移除，显示增删行数 |

- `makeSummary()` 不再拼接 CPL
- 模型子菜单改用 provider（B 级余额数据源），不再依赖 A 级 token 数据
- 仓库子菜单的 `cplStr` 替换为 `+added/-deleted`

## 3. 逻辑层变更

### 3.1 欢迎页 Step 3 — 仓库选择

**现状**：Onboarding 3 步（欢迎 → 侦测 → 完成），仓库选择仅在设置页。

**方案**：插入 Step 3，流程变为 4 步：

```
Step 0  欢迎/价值主张         （已有，无需改动）
Step 1  侦测结果             （已有，无需改动）
Step 2  逐项启用             （已有，无需改动）
Step 3  选择 Git 仓库        （新增）
Step 4  完成                 （已有，步号从 3 改为 4）
```

**Step 3 详细设计**：

- 标题 + 说明："选择要监控的 Git 仓库（可跳过，稍后在设置中配置）"
- 自动扫描默认目录：`~/dev`、`~/projects`、`~/code`（复用 `ReposTab` 扫描逻辑）
- 扫描进度指示器（扫描可能较慢）
- 结果列表：仓库名 + 路径 + 勾选框
- "跳过"按钮 + "完成"按钮
- 勾选结果持久化到 `repo_search_dirs` UserDefaults（已有存储键）
- 与 Step 1（侦测）内容不同——Step 1 是"发现了哪些工具"，Step 3 是"发现了哪些仓库"

## 4. 涉及文件

| 文件 | 变更类型 | 内容 |
|------|----------|------|
| `DashboardView.swift` | 重构 | 拆分图表、调整摘要卡、CPL 降级、代码变化图改为叠加正柱 |
| `MenuBarController.swift` | 修改 | 摘要行去 CPL/token、模型子菜单改为 B 级 provider、仓库子菜单改为增删行 |
| `OnboardingView.swift` | 新增功能 | 插入 Step 3 仓库选择 |

## 5. 约束

- **不改变数据模型**：不新增/修改数据库表
- **不改变 StatsService 接口**：复用现有 `dailyStats()`、`modelBreakdown()`、`repoBreakdown()`、`prediction()`
- **B 级余额子菜单**：复用 `ApiPoller.shared.cachedBalance()`，不新增轮询逻辑
- **向后兼容**：现有用户升级后设置不丢失；无 A 级用户的行为不变
- **i18n**：所有新增字符串走 `I18n.t()` 双语言

## 6. 验收标准

1. Dashboard 显示两张独立图表（花费图在上、代码变化图在下），不再有合并图
2. 花费图下层为订阅均摊（恒定值）、上层为 API 余额消耗（波动值），多 provider/工具叠加正确
3. 代码变化图新增和删除用两种颜色堆叠正柱，总柱高 = 变更总量
4. 摘要卡 avg CPL 移除，新增"本周增减行"和"订阅日均"
5. Dashboard 不再有独立 CPL 折线图，CPL 仅以数字小窗出现在底部辅助卡片行
6. 无 A 级用户不显示 CPL 小窗，显示引导卡片
7. 菜单栏今日/本周摘要不含 CPL 和 token 数
8. 菜单栏 Provider 子菜单显示 B 级余额数据
9. 菜单栏仓库子菜单显示增删行数
10. 欢迎页新增 Step 3（仓库选择），可扫描、勾选、跳过
11. 欢迎页 Step 4（完成）正确显示
